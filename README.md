# EXECUTIVE AI

Защищённое веб-приложение — цифровой офис помощника руководителя: календари, задачи и поручения, журнал действий. Требования — в [`docs/PRD.md`](docs/PRD.md), устройство — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

**Опубликовано:** https://executive-ai-zeta.vercel.app — обновляется автоматически при каждом изменении ветки `main`.

> ⚠️ До согласования с IT/ИБ используются **только вымышленные демо-данные**.

### Что требует согласования и пока выключено

- **AI** — включается `AI_PROVIDER=anthropic` и `ANTHROPIC_API_KEY` после согласования провайдера (PRD 9.3 п. 2). Без AI все функции работают вручную.
- **Google Calendar** — нужен OAuth Client тестового проекта (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`). До подключения интерфейс показывает «Не подключено».
- **OCR и распознавание речи** — не подключены: поля чеков вводятся вручную, расшифровка совещания — текстом.
- **Антивирус** — не подключён; у файлов честно показан статус «не проверен».
- **Email и Telegram** — уведомления только внутри приложения.
- **Отправка протоколов внешним адресатам** — нет; только экспорт.

## Требования

- Node.js 22+
- PostgreSQL 16 (локально или через Docker)

## Установка с нуля

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Поднимите PostgreSQL. Вариант с Docker (создаст обе базы — рабочую и тестовую):

   ```bash
   docker compose up -d
   ```

   Без Docker создайте пользователя `exec_ai` и базы `executive_ai` и `executive_ai_test` вручную.

3. Создайте файл настроек и задайте пароль демо-пользователей (не короче 12 символов):

   ```bash
   cp .env.example .env
   ```

   Откройте `.env` и заполните `SEED_DEMO_PASSWORD`, `APP_ENCRYPTION_KEY` и `FILE_SIGNING_KEY` (команда генерации ключа — в `.env.example`). Файл `.env` в Git не попадает.

4. Примените миграции и загрузите демо-данные:

   ```bash
   npm run db:migrate
   ```

   ```bash
   npm run db:seed
   ```

5. Запустите приложение:

   ```bash
   npm run dev
   ```

   Откройте http://localhost:3000.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Режим разработки |
| `npm run build` / `npm start` | Production-сборка и запуск |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm test` | Автотесты (на отдельной базе `TEST_DATABASE_URL`, она очищается) |
| `npm run db:generate` | Сгенерировать SQL-миграцию после изменения `schema.ts` |
| `npm run db:migrate` | Применить миграции |
| `npm run db:seed` | Загрузить демо-данные (идемпотентно) |

| `npm run worker` | Один проход планировщика (для cron, если встроенный выключен) |

Проверка после каждого этапа:

```bash
npm run typecheck && npm test && npm run build
```

## Безопасность — коротко

- Пароль входа хранится только как bcrypt-хеш (cost 12). Пароли и секреты сторонних сервисов приложение **не хранит**.
- Сессия: случайный токен 256 бит, в базе — только SHA-256. Cookie `HttpOnly; SameSite=Lax`, `Secure` в production, срок 12 часов.
- Блокировка: 5 неудачных попыток за 15 минут по email, 20 — по IP.
- Права проверяются на сервере в каждой функции сервиса; недоступная запись — «не найдено»; каждый отказ — в журнал.
- Журнал действий нельзя изменить или удалить — запрет на уровне триггера PostgreSQL.
- Заголовки: CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, HSTS (production).

Что нужно сделать **до работы с реальными данными** — раздел 9.2 PRD (HTTPS, MFA, шифрование, резервные копии, смена демо-пользователей).

## Известные ограничения

- Повторяющиеся события не поддерживаются.
- Ручного переключателя темы нет (тема — по настройке системы).
- Google Calendar синхронизирует только рабочий календарь с основным календарём аккаунта.
- Руководитель видит предложения во «Входящих» и может их отклонить; создать по ним событие или задачу может помощник (нужны права на соответствующий раздел).
- До работы с реальными данными — раздел 9.2 PRD: HTTPS, шифрование хранилища, обязательная MFA, смена демо-пользователей.
