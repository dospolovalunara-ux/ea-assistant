# CLAUDE.md — правила работы с проектом EXECUTIVE AI

Полные требования — `docs/PRD.md`. Архитектура — `docs/ARCHITECTURE.md`.

## Главное
1. Работать поэтапно. После каждого этапа: `npm run typecheck && npm test && npm run build`, затем коротко — что сделано и что осталось.
2. Объяснять простым языком, по-русски. Интерфейс — только на русском.
3. Секреты (ключи, OAuth secrets, пароли) — только в переменных окружения. Не в Git, не во frontend, не в коде, не просить вставлять в чат.
4. Только вымышленные данные.
5. Каждое AI-действие — проверяемый результат и ручной вариант. AI пишет только в `ai_extractions`, в рабочие таблицы пишет обычный серверный код после подтверждения человека.
6. Финансовые вычисления — только детерминированным кодом (SQL/TS), не моделью.
7. Критичные действия — только после подтверждения.
8. Права — на сервере. На каждое новое право — тест обхода роли в `tests/rbac.test.ts`.
9. Не утверждать, что интеграция работает, пока она не подключена и не проверена.
10. Если действие небезопасно или требует согласования — безопасная заглушка и объяснение.
11. Никаких фиктивных кнопок, интеграций и цифр. Нереализованное — серым с пометкой «В разработке».

## Архитектурные правила
- Страницы и Server Actions обращаются к базе **только** через `src/server/services/*`.
- Каждая функция сервиса получает `actor`, первой строкой проверяет права (`requirePermission`) и пишет журнал (`writeAudit`) в той же транзакции, что и изменение.
- Недоступная запись → `NotFoundError` («не найдено»), отказ → `access.denied` в журнал.
- Фильтр видимости — прямо в SQL-запросе (защита от IDOR).
- Ввод проверяется Zod в сервисе, ошибки — `ValidationError` с понятными сообщениями по полям.
- Время в базе — `timestamptz` (UTC). Пояс по умолчанию — `Asia/Almaty`. Работа с датами — `src/lib/time.ts`.
- Схема — `src/server/db/schema.ts`; миграции — `npm run db:generate` (SQL в `drizzle/`, хранится в Git). Ручные SQL (триггеры) — `drizzle-kit generate --custom`.
- Интеграции — через адаптеры в `src/server/integrations/*`.

## Next.js 16
- `middleware` называется `proxy` (`src/proxy.ts`). В нём только быстрая проверка наличия cookie; настоящая проверка — на сервере.
- `params`, `searchParams`, `cookies()`, `headers()` — асинхронные (`await`).

## Тесты
- Vitest на отдельной PostgreSQL (`TEST_DATABASE_URL`), база пересоздаётся в `freshDb()` (`tests/helpers.ts`).
- Тесты вызывают сервисы напрямую с `actor` нужной роли.
